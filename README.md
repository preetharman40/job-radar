# Job Radar

Finds DevOps / SRE / platform jobs in Canada by reading company ATS APIs
directly — the same endpoints a careers page calls — so a req surfaces within
minutes of being published instead of days later via LinkedIn or Google.

**374 boards · 8 ATS platforms · ~19,500 postings scanned in ~45 seconds.**

Design decisions, per-platform quirks, and the things that turned out not to
work: **[ARCHITECTURE.md](ARCHITECTURE.md)**.

---

## The 30-second version

```bash
cd ~/devops/jobs/radar && ./daily.sh
```

That is the whole daily routine. Everything below is for when you want
something specific.

## 1. `daily.sh` — every morning

```bash
cd ~/devops/jobs/radar
./daily.sh
```

Runs `--level entry,mid --min-score 8 --max-age 30`, writes `digest.md`, and
auto-files anything scoring 25+ into `../applications.md`.

It shows **only what is new since the last run**. Any flag you pass goes through
to the engine:

```bash
./daily.sh --all --family vendor
```

To reset its memory and start fresh:

```bash
rm seen.sqlite3 && python3 job_radar.py --seed
```

## 2. `job_radar.py` — the engine

| Flag | What it does |
|---|---|
| `--all` | Everything currently matching, not just new |
| `--seed` | Record current state silently (first run only) |
| `--level` | `entry,mid,senior,exec,intern` — **the biggest lever** |
| `--family` | `devops`, `adjacent`, `vendor` |
| `--bucket` | `CA`, `NA-REMOTE`, `MULTI` |
| `--min-score` | Default 8. Barely matters — nothing scores below 10 |
| `--max-age` | Days since posting, default 30 |
| `--track` | Append results to `applications.md` |
| `--track-min-score` | Default 25 |
| `--md FILE` | Write a markdown digest |
| `--targets` / `--workers` | Alternate board list / concurrency |

### Searches worth knowing

```bash
# Support roles at DevOps tool vendors — the best-converting family
./daily.sh --all --family vendor

# DevOps / SRE titles only
./daily.sh --all --family devops

# Include Senior — roughly doubles results (59 -> 117)
python3 job_radar.py --all --level entry,mid,senior

# Entry level only
python3 job_radar.py --all --level entry

# Canada-based only, drop the US/Canada ambiguous ones
python3 job_radar.py --all --bucket CA

# Posted this week
python3 job_radar.py --all --max-age 7
```

### Reading a result

```
### [32] Support Engineer (AMER)
- **gitlab** · Remote, Canada; Remote, United States
- `CA` · `mid` · posted 2d
- https://job-boards.greenhouse.io/gitlab/jobs/8654230002
- matched: bash, ci/cd, incident, kubernetes, linux, on-call, troubleshooting
```

| Field | Meaning |
|---|---|
| `[32]` | Resume fit. 25+ = apply today · 15–24 = this week · 8–14 = read it first |
| `CA` | You can hold it. `NA-REMOTE` = "US or Canada". `MULTI` = open it and check |
| `mid` | Detected level |
| `posted 2d` | Days since publication |
| `matched:` | Which of **your** resume skills appear in the description |

`matched:` is the most useful line. Judge a role by it, not by its title.

Occasionally you will see:

```
⚠️ location says Toronto but office tag is Atlanta — confirm on the job page
```

That means the req is genuinely Toronto-eligible but filed under another office
on the company's own careers site, so it is invisible to anyone filtering that
page by Toronto. Real job, fewer applicants — but verify on the posting.

## 3. `canada_employers.py` — for US-remote roles

A US company can only pay you if it has a Canadian entity, an Employer of
Record, or a contractor arrangement. You cannot tell from a job ad — but **any
Canadian posting on their board proves they are set up to employ here.**

```bash
python3 canada_employers.py --min-ca 1 --out ../canada_employers.md
python3 canada_employers.py --vendors --min-ca 1 --out ../canada_employers_vendors.md
```

**How to use it:** you see a "Remote — US" role at Okta. Check the table — Okta
has 59 Canadian roles, so employing you is a policy decision, not a legal
blocker. Worth an email. If a company is *not* in the table, skip its US-remote
roles; applying is a null action.

Pre-generated output is already in `../canada_employers.md`. Refresh monthly.

## 4. `discover.py` — identify one company's ATS

```bash
# Found a company you like — what do they run, and what is the endpoint?
python3 discover.py --url https://careers.somecompany.com

# Weekly health check — re-probe every board, prune the dead ones
python3 discover.py --verify --add

# Brute-probe a name across the token platforms
python3 discover.py --company "Vena Solutions"
```

`--url` recognises 26 ATS platforms, auto-resolves a Workday careers URL into a
paste-ready `{tenant, cluster, site}` block, and falls back to
robots.txt → sitemap when it finds no known ATS.

`--verify` probes twice. Concurrent probing trips rate limits, and a single
failure would otherwise look like a dead board and get a live target pruned.

## 5. `harvest.py` — add boards in bulk

Takes real company names and tests which ones have a board on Greenhouse,
Lever, Ashby, Recruitee or Rippling.

```bash
python3 harvest.py --wiki "Category:Companies based in Winnipeg" --add
python3 harvest.py --url https://some-page-listing-companies.com --add
python3 harvest.py --names "Vena Solutions" Nuvei --add
python3 harvest.py --file companies.txt --add
```

Drop `--add` for a dry run. Expect a 5–15% hit rate.

**You probably do not need this.** Going from 163 to 366 boards added **four**
matches — two thirds of what the new boards return is not reachable from Canada.
It is here for when the list goes stale, not as a weekly habit.

## 6. `hunt.py` — Workday and SuccessFactors tenants

These platforms hold the Canadian banks, insurers, telcos, universities and
public sector. They cannot be harvested by token — Workday needs a
tenant/cluster/site triple, SuccessFactors needs a careers base URL, and neither
is guessable (Loblaw's Workday tenant is `myview`; RBC's site is `RBCGLOBAL1`).

```bash
# Preferred: give the main domain, it finds the careers page itself
python3 hunt.py --names "Queen's University@queensu.ca" --add

# If you already know the exact careers host
python3 hunt.py --names "Scotiabank|jobs.scotiabank.com" --add

python3 hunt.py --file employers.txt --add
```

Higher quality than `harvest.py`, but low yield — **6 tenants from 94
employers**. Most large Canadian employers run custom SPAs with no readable ATS.

## Web view — `serve.py`

Read `applications.md` in a browser instead of a text editor, from any device on
your home network. Updates itself the moment cron files a new job.

```bash
cd ~/devops/jobs/radar
python3 serve.py
```

It prints both URLs:

```
  this machine : http://localhost:8737/
  on your LAN  : http://10.0.0.41:8737/
```

| Flag | Default | |
|---|---|---|
| `--port` | `8737` | |
| `--host` | `0.0.0.0` | reachable on your LAN. Use `127.0.0.1` for this machine only |
| `--file` | `../applications.md` | |

**What it does**

- Sortable table — click any column header
- Filters: all · to apply · 25+ · vendor · devops · done
- Text search — press `/` to focus, `esc` to clear
- Click a row to expand: matched keywords, next action, notes, checklist, and a
  direct link to the posting
- **Live updates.** The server watches the file's mtime and pushes over
  Server-Sent Events, so a job filed by cron appears without a refresh and
  flashes briefly. The dot next to the header shows connection state.

**It writes to `applications.md`** — status changes and deletes edit the file in
place, under an `flock` shared with the radar so cron appending at the same
moment cannot clobber your edits. Writes are atomic (temp file + rename).

**Status:** `toapply` → `applied` → `interviewing` → `rejected`. Marking a job
applied stamps today's date automatically. Deleting takes two clicks and is
remembered, so the next sweep does not re-add it.

**Expired jobs are hidden.** Every sweep records each URL it sees on any board;
a tracked job whose URL stops appearing has been taken down. Those drop out of
all views except the **expired** filter — hidden rather than deleted, so your
applied history survives.

**No authentication.** It binds to your LAN because that is what you asked for,
but it contains your application notes and hiring-manager contacts. Do not
port-forward it or expose it through a tunnel.

### Run it at boot

Installed as a systemd user service, so it survives logout, reboot and crashes:

```bash
systemctl --user status job-radar-web     # is it up
systemctl --user restart job-radar-web    # after editing serve.py
journalctl --user -u job-radar-web -n 30  # or: tail radar/web.log
```

The unit is in the repo as `radar/job-radar-web.service.example` — it uses `%h`
for your home directory, so it needs no editing:

```bash
mkdir -p ~/.config/systemd/user
cp radar/job-radar-web.service.example ~/.config/systemd/user/job-radar-web.service
systemctl --user daemon-reload
systemctl --user enable --now job-radar-web
loginctl enable-linger "$USER"      # required to start at BOOT
```

Three pieces make it durable:

- `systemctl --user enable` — starts with your session
- `loginctl enable-linger` — starts at **boot**, without you logging in. Skip
  this and a user service only runs while you are logged in, which defeats the
  point after an unattended reboot
- `Restart=always` — back within 3 seconds if the process dies

The unit is sandboxed (`ProtectSystem=strict`, `NoNewPrivileges`, `PrivateTmp`)
with write access limited to `~/devops/jobs`, since the app binds to your LAN
and has no authentication.

## Cadence

| When | Command | Why |
|---|---|---|
| **Daily, 5 min** | `./daily.sh` | New reqs |
| **Weekly, 10 min** | Open the links in `manual_check.md` | Employers with no readable ATS |
| **Weekly, 1 min** | `python3 discover.py --verify --add` | Prune dead boards |
| **Monthly** | `python3 canada_employers.py --min-ca 1 --out ../canada_employers.md` | Refresh the Canada-authorized list |
| **Quarterly** | `discover.py --url` on the `manual_check.md` employers | Career sites get replatformed |

```bash
crontab -e
```

```cron
*/30 8-19 * * 1-5 ~/devops/jobs/radar/daily.sh >> ~/devops/jobs/radar/radar.log 2>&1
```

catches a break — that is the argument for running it weekly.

## What this tool cannot do

- **11 employers are unreachable.** CGI (Njoyn, behind Radware bot manager),
  WestJet (Dayforce, client-side rendering), and nine custom careers SPAs with
  no ATS signature and no sitemap. They live in `manual_check.md`.
- **It does not find referrals**, which matter more than anything here.
- **It is not exhaustive.** 374 boards out of roughly 31,000 companies on these
  platforms. No ATS exposes a "list every board" endpoint.

## Honest note on priorities

Discovery is not usually the bottleneck. Most matches sit open for a median of
**15 days** — and long-lived reqs are common — while still accepting applications — so being applicant #5 rather
than #50 is a real but modest edge.

Ranked by what actually lands a DevOps job in Canada:

1. Referral or warm intro
2. A recruiter who knows you
3. A tailored application to a genuinely well-fit role
4. **Application speed** — this tool
5. Volume applying

Use it for five minutes a day, then spend the rest of the hour on 1–3. Adding
more boards has severe diminishing returns; sending the applications does not.
